# Your components

## 1. aria2 RPC server

Runs permanently in Linux/WSL:

```bash id="iyk7f4"
aria2c \
  --enable-rpc \
  --rpc-listen-all=true \
  --rpc-secret=mysecret \
  --dir=/home/wineo/dlmovies
```

Preferably as:

* systemd service
* auto-start on boot

---

# 2. FastAPI WebAPI

Your FastAPI becomes middleware/orchestrator.

It:

* talks to website
* manages login
* searches movies
* gets dlinks
* sends dlinks to aria2
* checks progress
* maybe pause/resume later

---

# 3. OpenClaw Agent

Only does reasoning + workflow.

It NEVER:

* manages Linux services
* runs shell commands
* manages download processes
* parses terminal logs

It only calls APIs.

This keeps agent simple and reliable.

---

# So yes, add these endpoints

---

# A. Check aria2 health

```python id="56lhmb"
GET /api/download/aria2/status
```

Example response:

```json id="q1ehuk"
{
  "status": true,
  "aria2_running": true
}
```

If dead:

FastAPI can try:

```bash id="tr81ot"
systemctl start aria2
```

then recheck.

---

# B. Start download

```python id="08ycg2"
POST /api/download/start
```

Body:

```json id="f46gvs"
{
  "url": "MOVIE_DIRECT_LINK"
}
```

FastAPI internally calls:

```text id="x9pjgh"
aria2.addUri
```

aria2 returns GID.

Example response:

```json id="q5gopj"
{
  "status": true,
  "gid": "2089b05ecca3d829"
}
```

---

# C. Get progress

```python id="fyv1y8"
GET /api/download/progress/{gid}
```

FastAPI internally calls:

```text id="1e4bll"
aria2.tellStatus
```

Example response:

```json id="cxdbuh"
{
  "status": "active",
  "progress_percent": 67,
  "download_speed": "5 MB/s",
  "completed": "1.2 GB",
  "total": "2 GB"
}
```

# Why this architecture is strong

Because each layer has one responsibility:

| Layer    | Responsibility     |
| -------- | ------------------ |
| OpenClaw | reasoning/workflow |
| FastAPI  | business logic     |
| aria2    | downloading        |
| systemd  | process lifecycle  |

This separation is very good engineering.

---

# One VERY important recommendation

Create a separate Python module:

```text id="ol2rgo"
aria2_client.py
```

Do NOT put aria2 logic directly inside endpoints.

Example structure:

```text id="my1l6x"
project/
├── main.py
├── filmaz_client.py
├── aria2_client.py
├── download_manager.py
```

---

# Example architecture

## aria2_client.py

Handles:

* RPC requests
* addUri
* tellStatus
* pause
* remove
* healthcheck

---

## download_manager.py

Handles:

* formatting progress
* validation
* business rules

---

## main.py

Only FastAPI routes.

This keeps your project scalable later.

---

# Final important note

You do NOT want OpenClaw directly touching:

* shell
* systemctl
* subprocess
* aria2 terminal

unless you are intentionally building a low-level autonomous Linux operator agent.

For your movie-downloader project:
API-oriented architecture is the correct design.
